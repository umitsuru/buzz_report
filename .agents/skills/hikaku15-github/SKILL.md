# Hikaku15 GitHub 更新スキル

## 目的
ユーザーが「投稿案No.Xを作って」「No.Xの画風を変えて」「GitHubの投稿案を更新して」と言ったら、手入力用の文章を返すだけで終わらせず、**利用可能なGitHub接続ツールを確認して、直接ファイルを読み書きする**。

対象リポジトリ：`umitsuru/buzz_report`
投稿案インデックス：`hikaku15/plans/index.json`
投稿案番号のフォルダ：`hikaku15/plans/001/`、`002/`、…
画風参考の実画像一覧：`hikaku15/studio/styles.json`
実際のX投稿の収集データ：`hikaku15/posts/numbers.json`、`posts/<folder>/raw.json`

## 接続の確認
1. この会話で利用可能なGitHub連携ツールを**実際に列挙・照会**する。過去に一度使えなかったというだけで「現在も使えない」と決めつけない。
2. GitHubが利用できる場合は、対象の `index.json` と `project.json` を読み、必要なフォルダと更新先を特定する。
3. ツールが利用できないときだけ、接続手順や他ツール向けの更新指示を案内する。その場合、実際に更新したとは決して言わない。

## 更新手順
1. **既存ファイルを読む**：対象フォルダの `common.md`、`project.json`、必要な `01.md`〜`10.md` と、投稿案一覧 `index.json` を確認する。
2. **ユーザーの指示を優先**：タイトル・登場人物・画風・比率・人物数・コマ割り・セリフ等を厳密に反映。過去の要望から明示変更された点は新要望を優先。
3. **共通設定の先頭・末尾**：作品の全体像・キャラの固定設定・画風・文字ルールを記述する。末尾に必ず「画像はまだ作らないでください。これは全スライドの共通設定を伝えるためのプロンプトです。これから各スライドの指示を出すので、次の指示を待ってください。」を含める。
4. **各ページの独立プロンプト**：1ページに1枚。番号 `n/10`、そのページの具体的な人物・服装・動作・表情・背景・吹き出し・オチ・注意点を明示。単なる概要ではなく、画像生成ボットが個別に使える完成版にする。
5. **JSONの整合性**：`project.json` の `plan_no`、`folder`、`project`、`format`、`aspect_ratio`、`image_count`、`pages`、`style` を一致させる。`index.json` の当該番号を更新し、**他の番号を上書きしない**。
6. **安全な書き込み**：更新対象のBlob SHAを取得し、`update_file` で既存のUTF-8テキストを書き換える。新規ファイルに `create_file` を使う。更新時に競合が起きたら最新を再取得して差分を確認する。
7. **画像は別管理**：ユーザーが生成を明示しない限り画像を作らない。古い `images/NN.jpg` は無断削除・上書きしない。新プロンプトと絵柄が食い違う場合はその事実を報告する。旧画像を隠す必要がある場合は `index.json` の対象プランへ `images_stale: true` を入れる（`plans/index.html` は旧画像を非表示にする）。**再生成が完了したら `images_stale` を外す／falseにして表示を再開する**。
8. **確認**：対象の `common.md`、ページファイル、`project.json`、`index.json` を読み直し、最新の条件が含まれるかチェック。必要に応じてGitHub Pagesの公開ワークフローを確認し、`in_progress` と `success` を区別する。
9. **報告**：更新に成功した場合だけコミット結果と以下のURLを提示。
   - 一覧：`https://umitsuru.github.io/buzz_report/hikaku15/plans/#plan-X`
   - GitHub：`https://github.com/umitsuru/buzz_report/tree/main/hikaku15/plans/XXX`

## 特記事項
- 書式A：複数コマ。書式B：左右対比の1枚絵。書式C：1ページ1人の図鑑。**アスペクト比は作品ごとの明示設定を優先**し、書式と固定で結びつけない。
- `GAFU-09` と `No.58` は異なる識別体系。番号を混同しない。参照元画像を閲覧できない場合は画風を見たふりをしない。
- ユーザーの「GitHubへ更新して」は、差し替え用文章の提示だけでなく、接続が利用可能なら**実際のGitHub更新の依頼**として扱う。
- 画像生成ボット・Claude・Grokbotの担当ファイルを尊重し、ユーザーが指定しない別フォルダや `posts/` の収集データは変更しない。

## 利用例
「投稿案No.5を独身女性10選に変え、今のヘタウマ画風を使って、GitHubも直接更新して」
「No.5の7枚目だけセリフを変えて、サイトへ反映して」
「GAFU-09の参考画像を使って、No.8の新しい10枚漫画案を保存して」

## このファイルの限界
これはGitHub上の再利用可能な手順書であり、**ChatGPTアカウントへ自動インストールされたスキルではない**。新しいChatGPTの会話で自動読み込みが保証されるわけではない。必要ならユーザーは「GitHubの .agents/skills/hikaku15-github/SKILL.md に従って」と指定する。GitHub連携を使用できるチャットなら直接更新する。
